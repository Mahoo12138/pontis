# Pontis v0.1.0-alpha.1 — 第一个对外可装的版本

**这是 alpha。** 功能范围就是 0.1.0 计划的全部范围，但发布验收（分发文档 §14）没有全部通过，所以它不应被当作"已支持手动安装和升级"的正式能力。下面"还没拿到什么"那一节是这份说明里最重要的部分，请先读完再决定要不要把你的书签交给它。

代码里的版本是 0.1.0；"alpha" 只存在于这个 tag 里。原因是扩展 manifest 的 `version` 只接受点分数字，塞不进预发布后缀——所以真正跑起来的每一处（`/meta`、下载页、扩展自身）报的都是 0.1.0。

| 项 | 值 |
| --- | --- |
| Server 版本 | 0.1.0 |
| HTTP API 版本 | v1 |
| 同步协议版本 | 1 |
| 数据库 schema 版本 | 20 |
| 扩展版本 | 0.1.0（两个包同为该版本） |

## 已经实测通过的

- 全新 Chrome Profile：加载已解压扩展 → 登录配对 → 创建绑定 → 初始对账 → 双向收敛。
- 同目录替换文件的升级：扩展 ID、`bootstrap.deviceId`、binding 状态、本地映射、applied 水位线、以及**升级前离线产生、尚未上传的改动**全部保留；服务端恢复后该改动正常上传、outbox 抽干。
- 安装包字节与安装页公布的 SHA-256 一致（真浏览器点击落盘核对过），两个包各自独立。
- CI 四个 job 全绿：Go（含 `-race`）、前端与协议、单二进制冒烟（含两个安装包的下载与摘要比对）、两个真实 Profile 的收敛与升级。
- 镜像启动冒烟：容器内 Web 可访问、数据卷可写、两个包可下载且匿名访问被拒。

## 还没拿到什么（alpha 的含义）

- **Edge 尚未盖章。** 全新 Edge Profile 的首装、配对、绑定、首次同步与离线排队都实测通过；但重启 Edge 后扩展页面会被浏览器以 `ERR_BLOCKED_BY_CLIENT` 拦下（Chrome 同路径正常）。用 `edge://extensions` 界面按钮加载的扩展是否也这样，还没人工确认——在那之前，Edge 属于"可能可用，别指望它跨重启"。
- **不提供 Firefox 安装包。** Firefox 正式版要求 Mozilla 签名。不要把 ZIP 改后缀当 XPI 装。
- **不提供 Safari 安装包。**
- **失败路径未系统验证**：下载中断、ZIP 损坏、解压失败、替换文件中途被打断，以及 IndexedDB 迁移失败时的行为，都还没有端到端测试。
- **Server × Extension 各自升级的兼容矩阵未测**，协议不匹配时的端到端表现也未测。0.1.0 是第一版，不存在"从旧版本升级"的场景；下一个版本之前必须补上。
- **没有经过"无开发背景用户"的全流程验收**（按页面指引完成安装、首次同步与一次手动升级）。这是分发文档规定的进入下一阶段的判断条件，目前未满足。
- **构建不可复现**：ZIP 内记录文件时间戳，同一份代码两次构建摘要不同。SHA-256 用来确认下载完整，不用于证明构建可重放。

## 装哪个

```text
pontis-server-linux-amd64
pontis-server-linux-arm64
pontis-server-darwin-arm64
pontis-server-windows-amd64.exe
ghcr.io/mahoo12138/pontis:v0.1.0-alpha.1     # linux/amd64、linux/arm64
```

预发布不会移动 `:latest`，也不会被标成正式版。先核对摘要再运行：

```sh
sha256sum --check SHA256SUMS
```

### 裸二进制

```sh
./pontis-server-linux-amd64
# 默认监听 :8080，数据写在当前目录的 ./data
```

配置走 TOML 或同名 `PONTIS_*` 环境变量：`listen`、`data_dir`、`public_url`、`trusted_proxies`、`log_level`、`shutdown_timeout`、`link_check_allow_cidrs`。放在反向代理后面时 `public_url` 与 `trusted_proxies` 都要配：会话 Cookie 的 `Secure` 是按请求算的，配错的方向两种都不安静。

### Docker

```sh
docker run -d --name pontis \
  -p 8080:8080 \
  -v pontis-data:/data \
  ghcr.io/mahoo12138/pontis:v0.1.0-alpha.1
```

最终镜像只有服务端二进制、TLS 根证书和一个数据目录，不含 Node.js、pnpm 或 WXT 运行时。以 uid `65532` 运行：具名卷属主继承自镜像可直接写；改用宿主目录 bind mount 时属主由宿主决定，需要先让该目录对 65532 可写。

### 浏览器扩展

扩展只从**你自己的实例**下载：登录后打开「设备」页，底部是安装包、SHA-256 与安装/升级步骤。这样保证装的一定是与运行实例配套的那一份，GitHub Release 也不公开镜像它。

两个包，按需要装**一个**：

- **标准同步扩展**——同步书签栏到 Pontis 空间，不改动新标签页。
- **起始页扩展**——在同步之外，把新标签页换成 Pontis 起始页。

接管新标签页无法做成扩展内的开关（浏览器只在安装时读取该声明），所以它只能是第二个包。两个都装会得到两套配对、两个同步引擎和本地两份相同书签；换装另一个包还会因解压目录不同而改变扩展 ID，需要重新配对。起始页扩展装入后、以及每次更新后，Chrome 与 Edge 都会先把它停用，需要在扩展管理页点「启用」——没点不是安装失败。

安装走开发者模式的「加载已解压的扩展程序」，因此会伴随浏览器的安全提示；这不是安装失败，也不需要为此关闭任何安全功能。

## 升级

**alpha 阶段请务必先备份。** 把整个数据目录（`pontis.db` 与 `backups/`）复制一份再替换二进制或换镜像标签——上面"失败路径未系统验证"意味着回退路径本身也没被验证过。迁移只前进，不自动回退。

扩展升级是手动的，产品不会自动拉取代码执行：在同一个永久目录里替换文件后点「重新加载」，**不要卸载**。扩展 ID、设备身份、绑定关系、水位线与本地尚未上传的改动都依附于那个 Profile，卸载会一起丢掉。导出书签不是等价备份，它保存不了尚未上传的操作。若升级后要求恢复（`RECOVERY_REQUIRED`），走 Pontis 的恢复流程；清空本地数据、删除绑定或卸载重装都不是恢复手段。

## 反馈

如果你打算试，请优先用一份**不是唯一副本**的书签（先在浏览器里导出一份）。最有价值的反馈是：你在哪个平台、按哪一步卡住、以及升级前后本地状态是否如你预期。

完整设计文档在仓库 `docs/` 下，分发链路的决策记录在 `pontis-extension-distribution-release-v1.md`。
