# Pontis v0.1.0

Pontis 是自托管的跨浏览器书签同步平台：一个 Go 二进制内含 Web 控制台与浏览器扩展安装包，数据全部留在你自己的机器上。

这是第一个发布版本。以下声明相互独立，因为它们的兼容范围各自不同：

| 项 | 值 |
| --- | --- |
| Server 版本 | 0.1.0 |
| HTTP API 版本 | v1 |
| 同步协议版本 | 1 |
| 数据库 schema 版本 | 20（迁移文件 `server/migrations/000020_*.sql`） |
| 扩展版本 | 0.1.0（两个包同为该版本） |

## 装哪个

产物按平台命名：

```text
pontis-server-linux-amd64
pontis-server-linux-arm64
pontis-server-darwin-arm64
pontis-server-windows-amd64.exe
ghcr.io/mahoo12138/pontis:v0.1.0     # linux/amd64、linux/arm64
```

先核对摘要，再运行：

```sh
sha256sum --check SHA256SUMS
```

### 裸二进制

```sh
./pontis-server-linux-amd64
# 默认监听 :8080，数据写在当前目录的 ./data
```

配置项走 TOML 或同名 `PONTIS_*` 环境变量：`listen`、`data_dir`、`public_url`、`trusted_proxies`、`log_level`、`shutdown_timeout`、`link_check_allow_cidrs`。数据库路径由 `data_dir` 推导，不单独配置。

放在反向代理后面时把 `public_url` 设成对外地址，并把代理地址加入 `trusted_proxies`——否则会话 Cookie 不会被标记为 `Secure`。

### Docker

```sh
docker run -d --name pontis \
  -p 8080:8080 \
  -v pontis-data:/data \
  ghcr.io/mahoo12138/pontis:v0.1.0
```

镜像的最终层只有服务端二进制、TLS 根证书和一个数据目录，不含 Node.js、pnpm 或 WXT 运行时。数据目录以 uid `65532` 运行：用具名卷（如上例）时属主由镜像决定，可直接写；改用宿主目录 bind mount 时属主由宿主决定，需要先让该目录对 65532 可写，否则会在启动日志里看到写不进数据目录的错误。

### 浏览器扩展

扩展不从浏览器商店分发，由**你自己的实例**提供：登录后打开「设备」页，底部就是安装包、SHA-256 与安装步骤。这样能保证装的一定是与当前运行实例配套的那一份。

有两个包，按需要装**一个**：

- **标准同步扩展**——把书签栏同步到 Pontis 空间，不改动新标签页。
- **起始页扩展**——在同步之外，把新标签页换成 Pontis 起始页。

接管新标签页无法做成扩展内部的开关（浏览器只在安装时读取该声明），所以它只能是第二个包。两个都装会得到两套配对、两个同步引擎和本地两份相同的书签；从其中一个换成另一个也会因为解压目录不同而改变扩展 ID，需要重新配对。

安装是「开发者模式 + 加载已解压的扩展」，因此会伴随浏览器的安全提示。这不是安装失败，也不需要为此关闭任何安全功能。

## 升级

### 服务端

迁移只前进，不会自动回退。升级前先把整个数据目录备份一份（`pontis.db` 与 `backups/` 都在里面），再替换二进制或换镜像标签重启即可。

### 扩展

升级是手动的，产品不会自动拉取代码执行。步骤写在「设备」页的「手动升级」里，要点是：**不要卸载**，在同一个永久目录里替换文件后点「重新加载」。扩展 ID、设备身份、绑定关系、水位线与本地尚未上传的改动都依附于那个 Profile，卸载会一起丢掉。导出书签不是等价备份——它保存不了尚未上传的操作。

如果升级后要求恢复（`RECOVERY_REQUIRED`），走 Pontis 的恢复流程；清空本地数据、删除绑定或卸载重装都不是恢复手段。

## 已知限制

发布前应当知道的事实，不是待办的礼貌说法：

- **浏览器商店未上架。** Chrome/Edge 走开发者模式手动加载与手动升级，没有一键安装，也没有商店级自动升级。
- **Edge 尚未盖章支持。** 全新 Edge Profile 的首装、配对、绑定、首次同步与离线改动排队都实测通过；但对同一 Profile 完全不改动文件、只是退出再启动 Edge，扩展页面会被浏览器以 `ERR_BLOCKED_BY_CLIENT` 拦下（Chrome 同路径正常）。用界面按钮加载的扩展是否也会这样，尚未由人工确认——因此发行清单里的「已实测浏览器」只记 Chrome，安装页对 Edge 明写「尚未实机验证」。
- **不提供 Firefox 安装包。** Firefox 正式版要求扩展经过 Mozilla 签名，未签名的包无法长期保留。不要把 ZIP 改后缀当作 XPI 安装。
- **不提供 Safari 安装包。**
- **服务端与扩展的兼容矩阵未做系统测试。** 0.1.0 是第一个版本，不存在"从旧版本升级"的场景；协议不匹配时的行为也没有端到端验证过。下一个版本之前需要补上。
- **构建不可复现。** ZIP 内记录了文件时间戳，因此同一份代码两次构建得到的扩展包摘要不同。摘要用于确认下载完整，不用于证明构建可重放。
- **没有双提交 CSRF token。** 会话 Cookie 是 `HttpOnly` + `Lax`，且带 Cookie 的写请求必须与实例自身同源。在这套同源拓扑下这比双提交更强，所以那层没有做。
- **`trusted_proxies` 目前只用于判断能否相信 `X-Forwarded-Proto`。** `X-Forwarded-For` 没有任何消费者：不记录、也不按客户端地址限流。
- **链接检查以服务端自身的网络身份发起。** 默认只允许访问公网可路由地址；内网书签需要显式配置 `link_check_allow_cidrs`。
- **安装包只从实例下载。** GitHub Release 只附服务端二进制，不公开镜像扩展包，避免出现「装的和运行的不是同一份」。

## 这一版做了什么

- 服务端：规范书签树、同步空间与挂载、增量同步与冲突对账引擎、初始重同步恢复、备份与保留策略、撤销与活动流、链接检查与整理、导入导出、跨空间转移、广场发布、多用户与 API Token、后台任务与定时调度。
- Web 控制台：书签浏览器、详情面板、整理、分析、任务、设备、备份、管理。
- 浏览器扩展：设备配对、书签双向同步、离线待上传队列、初始对账交互、起始页与新标签页接管、本实例更新提示。
- 分发：扩展安装包随二进制内嵌，实例内下载，带 SHA-256 与安装/升级指引。

设计文档在仓库的 `docs/` 下，分发的完整决策记录在 `pontis-extension-distribution-release-v1.md`。
