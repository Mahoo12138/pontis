# Pontis v0.1.0-alpha.2

**这仍然是 alpha。** 它相对 `v0.1.0-alpha.1` 变化的是四个用户可见问题与一处镜像构建方式，验收状态没有变化：分发文档 §14 的门槛仍未全部通过，alpha.1 说明里「还没拿到什么」那一节**逐条继续成立**，请先读那一节再决定是否把书签交给它。

安装、升级与回退的步骤与 alpha.1 完全相同，本页不重复；需要时看 [`v0.1.0-alpha.1.md`](./v0.1.0-alpha.1.md)。

代码里的版本仍是 0.1.0，「alpha.2」只存在于这个 tag 里——扩展 manifest 的 `version` 只接受点分数字。因此 `/meta`、下载页与扩展自身报出的版本与 alpha.1 相同，**不能靠版本号区分两者**，只能靠 tag 与安装包摘要。

| --- | --- |
| Server 版本 | 0.1.0 |
| HTTP API 版本 | v1 |

## 相对 alpha.1 的变化

### 空间可以重命名与删除（`ed0a102`）

Web 控制台的侧栏空间行新增操作菜单，可改名、可删除。删除**只允许空空间**：服务端在同一事务内先确认归属，再检查节点、设备绑定、备份、发布与计划五类占用，任一存在即返回 `409 SPACE_NOT_EMPTY`；通过后才清理根目录槽位与用户的默认空间引用。这不是一个「连带删除所有内容」的开关——想删掉一个空间，先把里面的书签与文件夹删除，再删这个空壳。

### 嵌套文件夹与其内书签可以一并多选删除（`5d4aea0`）

此前选中一个文件夹和它里面的书签后一起删除会失败：客户端把子孙节点与文件夹一并提交，服务端级联删除后第二个请求返回 `unknown node`，整批中断。现在选择规则（按存在性裁剪选区、点击与 ⌘/Shift 的区间计算、双击展开前保留既有选区）抽为纯函数，删除只提交最小节点集；列表的多选沿用文件管理器式的选择语义。

### 同步不再每五分钟留下一条跳过记录（`6ccee81`）

唤醒与定时器同时触发时，两轮会争用同一绑定的运行锁，输掉的那轮写入「另一轮正在处理该绑定，本轮跳过」，在诊断日志里表现为周期性噪声。现在同一时刻只允许一轮在跑，后到的触发登记为一次补跑，等当前轮结束后执行；去抖触发仍然保证最后一次修改会被同步出去。

### 扩展设置页重构（`740cce4`）

- 起始页配置按「当前来源 → 外观 → 显示 → 新标签页」分段，每段一个标题加一行说明；「选择来源」与「外观」两处收进对话框，卡片上只留一行摘要与一个入口；未选定来源时不再渲染「外观」与「显示」。
- 设置页组件按模块拆分（同步状态、账号、诊断、重同步决策、空态），并补充渲染测试与一组源码不变量守卫。
- 修掉同页的一个缺陷：设备身份此前排在书签树遍历之后读取，书签树读取卡住或失败时，**已配对的设备重新打开设置页会显示「这台浏览器还没有配对」**。现在身份由刷新循环最先读取。

### 多架构镜像的构建方式修正（`0c309bf`）

需要执行代码的阶段（安装依赖、构建前端、编译）此前没有固定平台，多架构构建会在目标架构下真的去跑另一架构的 node 与 go，而 runner 默认没有注册 binfmt。现在这些阶段固定在构建平台，最终镜像按目标架构各取自己的 distroless 基底，交叉构建不再依赖宿主能执行外架构二进制。已在 arm64 宿主上按 `linux/amd64` 交叉构建，容器启动后 `/healthz` 正常应答。

## 本次改动自身的验证状态

- 上述改动有自动化覆盖：Go 19 个包、前端与扩展 550 个用例，以及扩展设置页的无头浏览器实测（含两个对话框的打开、焦点圈定与 Esc 关闭）。
- **没有**经过多 Profile、多浏览器的人工验收。空间删除只验证到接口与事务边界，以及「删掉当前正在看的空间」这一条路径；「删掉当前默认空间」与多标签同时打开同一空间时的表现未做端到端人工确认。
- 起始页配置的重构只在 Chrome 无头环境验证过；Edge 与真实桌面 Profile 下的表现未测。

## 装哪个

```text
pontis-server-linux-amd64
pontis-server-linux-arm64
pontis-server-darwin-arm64
pontis-server-windows-amd64.exe
ghcr.io/mahoo12138/pontis:v0.1.0-alpha.2     # linux/amd64、linux/arm64
```

预发布不会移动 `:latest`，也不会被标成正式版。先核对摘要再运行：

```sh
sha256sum --check SHA256SUMS
```

浏览器扩展只从**你自己的实例**下载：登录后打开「设备」页，底部是安装包、SHA-256 与安装/升级步骤。两个包按需要装**一个**（标准同步 / 起始页），接管新标签页无法做成扩展内的开关，所以它只能是第二个包。

## 升级

**alpha 阶段请务必先备份。** 复制整个数据目录（`pontis.db` 与 `backups/`）再替换二进制或换镜像标签。迁移只前进，不自动回退。

扩展升级是手动的：在同一个永久目录里替换文件后点「重新加载」，**不要卸载**。起始页扩展每次更新后 Chrome 与 Edge 都会先把它停用，需要在扩展管理页点「启用」。由于版本号仍是 0.1.0，扩展自身不会提示「有更新版本」——判断依据是安装页公布的摘要。

## 反馈

请优先使用一份**不是唯一副本**的书签。最有价值的反馈仍然是：你在哪个平台、按哪一步卡住、升级前后本地状态是否如你预期。完整设计文档在仓库 `docs/` 下，分发链路的决策记录在 `pontis-extension-distribution-release-v1.md`。
