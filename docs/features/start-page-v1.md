# Pontis 起始页 V1：功能设计与实施规范

版本：V1.0  
日期：2026-10-12  
状态：功能设计基线；浏览器新标签页接管的最终分发方式待发布前确认  
适用范围：Pontis Web、浏览器扩展、服务端只读数据接口  
设计主题：**Cold Rational Workspace / 冷灰理性工作台**

本文整理已讨论的起始页方案，并补充实施边界、异常处理与验收要求。文中的新增接口、数据结构和目录均为建议设计，不表示当前仓库已经实现；本次未重新审查仓库代码，也不改变现有同步协议的版本与语义。

## 0. 实现修订（2026-10-12）

落地时改动了本文的两处设计。以下修订优先于正文中与之冲突的表述。

**0.1 取消 `StartPageReadGrant`，来源授权按同步绑定派生。**

正文 §5.3、§11.2、§13.1 设想的是"账户批准一个来源文件夹"，因此扩展每次变更来源都要重新做一次账户确认。实现时发现这个前提不成立：设备凭据本来就能读取它**已绑定空间**的全量快照（`GET /api/v1/sync/bindings/{id}/snapshot`），所以"显示其中某个目录"不构成任何范围扩大，独立 Grant 只是把一次本不需要账户参与的本地选择变成了账户操作。

现在的规则：

1. 设备可以显示某个目录，当且仅当它对该目录所属空间存在 **active 绑定**——与 `/sync` 自身快照读取同一道门槛，不新设第二套判断。
2. 来源（`space_id + folder_id`）是扩展的本地配置，写入 `startPageConfigs`，不产生任何服务端状态。
3. 扩展内**不存在账号密码输入**：设备凭据足以完成读取，账户凭据不再参与起始页。
4. 代价：起始页不能显示这台浏览器未同步的空间里的目录，正文 §5.3 举的"只同步工作、但起始页显示个人/日常入口"场景在 V1 不支持。将来确实需要时，再引入跨空间的只读批准，而不是现在就为它保留一张空表。

仍然不变的边界：来源失效不自动退回整个空间；绑定被解除后即使 ETag 未变也不得返回 304；起始页不创建绑定、不写 Pending、不推进 watermark。

**0.2 新标签页接管做成可选构建产物，不是设置开关。**

`chrome_url_overrides` 由 Chrome 在安装时读取，之后没有任何 API 可以改它，因此"用起始页接管新标签页"不可能是标准扩展里的一个复选框。实现方式与 §9.1 的建议一致：

1. `PONTIS_NEWTAB=1 pnpm build:newtab` 产出接管构建，输出到 `extension/.output-newtab/`，扩展名为「Pontis (起始页)」，入口 `entrypoints/newtab` 复用 `entrypoints/start-page` 的同一个 App 组件。
2. 默认构建通过 `entrypoints:resolved` 钩子移除 `newtab` 入口：产物里既没有 `newtab.html`，也没有覆盖声明。这保证只提供同步能力的标准扩展不会因为多了起始页而在普通升级后接管新标签页（§9.2）。
3. 两套产物使用不同的扩展名与输出目录，避免互相覆盖或被误认成对方的更新。
4. 设置页直接说明当前安装的是哪个版本、以及恢复原生新标签页实际要做什么，不提供会误导的伪开关（§8.3）。
5. 接管构建的第一条使用代价：浏览器把新标签页覆盖当成受保护设置。Edge 在安装或更新带 `chrome_url_overrides.newtab` 的扩展时会把它**自动停用**并弹出 "This extension tried to change your new tab page setting"，只有用户点 "Turn on" 才生效，每次更新后可能重复。这是 §9.2"不得在用户不知情时接管新标签页"的浏览器实现，不是 Pontis 能绕开的行为，也不能包装成"装好即接管"。阶段 C 的验收里"安装后新标签页没变"必须先排除这一条。

§9.3 的"薄扩展 vs 可选构建"因此按**可选构建**落地；若将来需要独立身份与独立更新渠道，再拆成薄扩展。

**0.3 不提供 Web `/start` 页面。**

正文 §2、§4.2、§13.1 中的普通网页起始页未实现，也不在 V1 计划内：起始页的价值在于接管浏览器的新标签页，而这只有扩展能做。Web 工作台保持原有的管理与整理职责。

## 1. 产品定位

**Pontis 起始页是现有书签树的快速访问视图，不是另一套导航收藏系统。**

Pontis 工作台负责管理、整理和维护书签；起始页负责日常搜索、浏览常用目录和快速打开网站。两者使用同一份 Canonical 书签数据，但拥有不同的信息密度和操作边界。

用户为当前浏览器选择一个 Space 中的文件夹作为来源。起始页上方提供搜索框，下方展示该文件夹中的书签与子文件夹。之后在工作台或已同步浏览器中进行的修改，经 Server 确认后反映到起始页，不需要再次导入或发布。

V1 不替换现有工作台首页，不默认改变用户的启动页、Home 按钮、默认搜索引擎，也不要求关闭 Edge 等浏览器原有同步服务。

### 1.1 目标

让用户打开起始页后，可以直接访问常用书签或发起搜索；Server 暂时不可达时，扩展页面仍能展示已有本地缓存；来源配置、读取授权和书签同步彼此独立，不因增加展示功能扩大写权限。

### 1.2 核心判断标准

起始页的成功标准不是承载更多组件，而是以很少的配置，让已有书签更容易使用。凡是需要维护第二份书签、第二套排序，或者新增页面编排系统的能力，默认不进入 V1。

## 2. 术语与入口

产品统一使用「起始页」命名，不使用含义模糊的「首页同步」。浏览器的启动页、Home 按钮主页与新标签页是不同入口，不能在界面中混称。Chrome 官方帮助和扩展文档分别说明了这些入口。[R1][R2]

| 入口 | V1 定位 | 接入原则 |
|---|---|---|
| Pontis 工作台 | 管理与整理书签 | 保持既有入口和路由 |
| 扩展内起始页 | 本地展示、预览与缓存 | 随扩展打包，可由 Popup／Options 打开 |
| 浏览器新标签页 | 主要日常使用场景 | 用户明确选择后使用对应接管版本／扩展 |
| 浏览器启动页／Home 按钮 | 可选的浏览器设置 | 提供设置说明，不在 V1 自动修改 |

`/start` 不是公开分享链接。普通网页访问必须验证当前用户身份，不能通过在 URL 中附带 Device Token 或 API Token 绕过登录。

## 3. V1 范围

### 3.1 必须交付

| 能力 | V1 定义 |
|---|---|
| 来源配置 | 一个 Space 中的一个真实文件夹 |
| 书签展示 | 当前层级的书签与子文件夹，轻量网格 |
| 文件夹浏览 | 点击进入子文件夹，面包屑返回 |
| 网页搜索 | 默认搜索引擎能力适配；不可用时显式选择搜索引擎 |
| 书签搜索 | 在配置来源文件夹及其完整子树内进行本地搜索 |
| 打开方式 | 默认当前标签；允许选择新标签 |
| 外观 | 沿用 Mantine Theme，支持系统／浅色／深色与两种密度 |
| 扩展缓存 | 先读有效缓存，再异步刷新，不依赖网络完成首屏 |
| 管理入口 | 跳转到对应工作台目录，不在起始页直接编辑 |
| 状态处理 | 未配置、空目录、离线、来源失效、授权失效等明确状态 |
| 浏览器接入 | 本地预览入口；明确的新标签页接管与恢复说明 |

**完整的「新标签页起始页 V1」交付需要完成接管方式验证。** 只有可预览页面而未确定接管分发时，应称为内部预览，不能宣称新标签页功能已完整发布。

### 3.2 明确不做

V1 不做多 Space／多目录聚合、标签组合视图、独立首页收藏、首页专属排序、拖拽布局、内联编辑、批量管理、公开导航站，以及天气、时钟、待办、每日一句、背景轮播和自定义小组件。

不做远程搜索建议、搜索历史云同步、浏览行为统计，也不自动跟踪网站访问频率来调整顺序。PWA 与普通 Web 页面的完整离线启动能力不在本次范围内。

## 4. 信息架构

### 4.1 起始页与工作台并列

起始页使用 `StartPageLayout`，不继承工作台常驻 Sidebar、管理导航、Explorer 表头或右侧 Inspector。页面仅保留 Pontis 标识、搜索区域、来源导航、书签区域和少量辅助操作。

主工作台可以提供一个「打开起始页」快捷入口，但不将起始页塞入管理员系统设置，也不把它变成默认登录后的强制落点。

### 4.2 配置入口

扩展 Options 中增加「起始页」分区，负责当前浏览器的来源与展示配置；Popup 提供「打开起始页」和「起始页设置」。起始页右上角的设置入口返回同一份配置，不维护第二份表单状态。

Web 版在起始页内提供设置入口，其偏好属于当前浏览器站点环境。V1 不做账户级偏好同步，也不假定 Web 页与扩展页能够自动共享本地存储。

### 4.3 页面基本结构

```text
Pontis 起始页                              工作台   设置

                    [ 网页 ▼ | 搜索内容…… ]

个人 / 日常入口 / 开发                          返回来源

[ Go 官方文档 ] [ React 文档 ] [ GitHub ] [ 工具文件夹 ]
[ ……          ] [ ……         ] [ ……     ] [ ……         ]

                                       内容已更新 · 刚刚
```

这只是结构示意。正式页面不显示桌面窗口的最小化／关闭按钮，不增加「专业版」等未定义的商业化标识。

## 5. 来源文件夹模型

### 5.1 使用 Canonical ID

来源保存 `spaceId + folderId`，其中 `folderId` 是 Server Canonical Node ID，不是浏览器 Bookmark ID，也不是目录路径字符串。

V1 只允许选择一个 `type = folder` 的真实节点。直接选择整个 Space、Root Slot 或任意多个目录不在本次范围内，避免引入多 Root 展示和聚合规则。未来需要支持时，应扩展来源类型，而不是用特殊空字符串冒充文件夹。

### 5.2 身份变化规则

| 事件 | 起始页行为 |
|---|---|
| 来源文件夹重命名 | 保持绑定，更新名称 |
| 来源文件夹在同一个 Space 内移动 | 保持绑定，更新已授权的展示信息 |
| 来源子树内容变化 | 刷新快照，按 Canonical 结构展示 |
| 来源文件夹被删除 | 标记来源失效，不自动改用其他目录 |
| 创建了一个同名文件夹 | 不按名称重新绑定 |
| 来源通过跨 Space 转移生成了新身份 | 视为原来源失效，需要重新选择 |
| 来源失效后又通过撤销恢复 | 要求用户重新确认来源，不擅自恢复已失效配置 |
| Space 被删除或读取权限撤销 | 停止展示并清理该来源缓存 |

**任何失效都不得自动退回整个 Space。** 这既是导航稳定性要求，也是避免意外扩大私人内容展示范围的要求。

### 5.3 来源范围与同步范围独立

起始页选中某个文件夹，不创建新的 Sync Binding，不新增 Browser Mount，不改变 Full／Partial 模式，也不修改原有设备的同步范围。

例如，当前浏览器只同步「工作」Space，但可在获得明确只读授权后，将「个人／日常入口」作为起始页来源。反过来，取消起始页来源也不意味着解除该 Space 的同步绑定。

起始页读取的是 Server 已确认的只读投影。尚未被 Server 接受的本地 Pending 修改不属于这份基线，V1 不为起始页额外实现乐观合并。

## 6. 书签区域与导航

### 6.1 当前层级展示

默认展示配置文件夹的直接子项。子文件夹作为入口卡片显示，点击后进入它的下一层；不递归铺开全部书签，不按一级文件夹自动展开分组。

每次新开起始页，回到配置的来源文件夹。当前下钻路径和搜索词属于当前标签页状态，不作为全局持久偏好。浏览器后退／前进应能恢复本标签内的文件夹导航，但不能导航到授权来源之外。

### 6.2 顺序

严格使用 Canonical sibling position，文件夹与书签保持原有相对顺序，不自动进行“文件夹优先”、字母排序或访问频率排序。标题搜索的排序与书签展示顺序可以不同，但搜索结果不能反向修改 Canonical position。

如果快照中出现重复位置，可用 Node ID 做稳定展示兜底并记录非敏感诊断；不得把异常展示顺序回写 Server。

### 6.3 入口内容

普通书签显示图标、标题和弱化的域名；文件夹显示文件夹图标、名称和可选的直接子项数量。长标题进行视觉截断，但应保留可访问名称和查看完整标题的方式。

不显示更新时间列、Revision、设备来源、勾选框、批量操作栏或常驻详情。低频操作只保留「复制链接」和「在工作台中管理」等只读辅助能力。

### 6.4 进入工作台

管理操作跳转到对应 Space 与节点所在位置，使用受控的内部深链接。需要单独登录时走正常 Web Session 流程，不在地址参数中传递扩展凭据。

第一版不在起始页重命名、删除、移动或拖拽排序，以免混淆“修改展示布局”和“修改所有设备共享的真实书签树”。

### 6.5 刷新期间的导航变化

后台刷新完成后，如果当前浏览的子文件夹仍在来源内，保留当前位置；如果它被删除或移出来源，则返回配置的来源文件夹并给出轻量提示。

如果失效的是配置的来源文件夹本身，不允许自动回退，必须进入来源失效状态。

## 7. 搜索设计

### 7.1 两种显式模式

搜索框左侧提供「网页／书签」切换，默认使用网页模式，并记住当前浏览器最后选择的模式。模式切换保留本次输入，但不会自动提交。

网页模式的 Enter 只执行网页搜索，不自动打开某个同名书签；书签模式的 Enter 只作用于已明确选中的结果，没有选中结果时不猜测目标。

空字符串不提交。输入内容看起来像 URL 时，V1 也不自动改成地址导航；网页模式仍按搜索词处理。

### 7.2 网页搜索

扩展端优先使用浏览器默认搜索能力。Chrome 的 `chrome.search.query()` 通过默认搜索提供商提交查询，需要 `search` 权限，并可指定当前标签或新标签展示结果。[R3]

通过 `SearchAdapter` 隔离浏览器差异，不把 `chrome.*` 调用写进共享 React 组件。其他浏览器要经过能力检测和真实测试；普通 Web 页不能假定拥有扩展搜索 API。

默认能力不可用或权限被拒绝时，提示用户选择明确的搜索引擎，不静默替换成产品指定的商业提供商。Web 版首次使用需要选择一个支持的搜索引擎。

V1 仅提供代码中登记的预设引擎，不开放任意脚本或可执行搜索模板。请求必须正确编码搜索词，只在用户主动提交后导航，不通过 Pontis Server 代理网页搜索。

新标签页中的搜索调用必须指向用户提交操作所在的标签，不能因为后台异步等待而误操作另一个刚获得焦点的标签。优先在页面上下文完成提交；跨后台处理时显式传递并校验目标。

### 7.3 书签搜索

搜索范围固定为**配置来源文件夹及其整个子树**，不随当前下钻目录隐式缩小，也不扩展到其他 Space。搜索框或结果区应显示「搜索日常入口内的书签」等范围提示。

使用当前完整本地快照搜索标题、URL 与文件夹名称，不把关键词发送到第三方或 Server。搜索用的大小写折叠等处理仅影响匹配，不修改实际保存的 URL，也不改变 Pontis 的身份与重复判断规则。

建议排序为标题精确匹配、标题前缀、标题包含、URL 包含；同等级保留稳定树遍历顺序。文件夹结果可以进入对应文件夹，书签结果按打开方式导航，结果展示相对于来源的路径以区分同名项。

没有结果时显示空结果状态，不自动切换到网页搜索。若需要网络搜索，应由用户显式切换模式后提交。

### 7.4 键盘与焦点

必须支持 Tab 导航、可见焦点、方向键选择搜索结果、Enter 打开和 Escape 退出结果状态。处理中文输入法 composition，避免候选词确认触发搜索提交。

不默认抢占地址栏焦点，不接管浏览器的全局快捷键。Chrome 文档明确指出，新标签页初始键盘焦点优先在地址栏，页面不能依赖自身输入框默认获得焦点。[R2]

V1 不增加远程搜索建议，不记录跨会话搜索历史。网页搜索提交失败时保留输入并由用户重试，不在后台自动重发。

## 8. 浏览器级配置

### 8.1 配置项

| 配置项 | 默认值／行为 | 作用域 |
|---|---|---|
| 来源空间与文件夹 | 未配置；用户明确选择 | 当前 Profile 与账户 |
| 搜索模式 | 网页；记住上次选择 | 当前 Profile 与账户 |
| 搜索提供商 | 扩展优先浏览器默认；Web 需明确选择 | 当前环境 |
| 打开方式 | 当前标签 | 当前 Profile 与账户 |
| 主题 | 跟随系统 | 沿用 Pontis 主题来源 |
| 密度 | 标准，可切换紧凑 | 当前 Profile 与账户 |
| 缓存内容 | 默认开启；退出／解除授权时清理 | 当前账户与来源 |

书签默认打开方式同时用于网页搜索结果。Ctrl／Cmd 点击、中键等浏览器原生操作应保持可预期，不被自定义 click handler 无条件覆盖。

### 8.2 配置流程

用户打开扩展「起始页设置」，选择 Space，再选择文件夹，查看来源名称和预览；涉及新增读取范围时完成授权确认。保存后获取第一份完整快照，展示配置成功与「预览起始页」。

目录选择器只显示可选择的文件夹，支持逐层浏览，不要求一次加载账户的所有书签。尚未加载完的数据不能误显示成“没有文件夹”。

保存新来源时，先准备并验证新授权与快照，成功后原子切换配置和活动缓存。若用户主动执行“解除来源”，则立即解除，不保留旧来源作为自动回退。

### 8.3 不设置伪能力开关

「预览起始页」「配置来源」「使用为新标签页」是不同动作。普通配置布尔值不能被描述成已经恢复浏览器原生新标签页。

在新标签页覆盖仍然存在时，不能用空白页或跳转回 `chrome://newtab` 的方式冒充“已关闭接管”。设置文案应明确告诉用户当前使用的安装版本，以及实际需要执行的关闭或恢复步骤。

## 9. 浏览器新标签页接入与分发

### 9.1 平台约束

新标签页覆盖通过 Manifest 的 `chrome_url_overrides.newtab` 声明，目标必须是扩展内打包的 HTML，而不是远程 URL。[R2][R4]

WXT 的 `entrypoints/newtab/index.html` 等 `newtab` 入口会自动生成新标签页覆盖声明。因此，不能仅为了预览创建该入口并把它加入所有默认构建。[R5]

建议先提供普通扩展页面 `entrypoints/start-page/index.html`，用于显式打开和预览；确认分发方案后，接管入口复用同一个页面组件。上述目录仍需按项目现有 WXT 配置接入。

### 9.2 已确定的约束

现有只提供同步能力的标准扩展，不应在普通升级后未经用户明确选择就接管新标签页。起始页不得要求关闭浏览器原有同步服务，不修改默认搜索引擎、不自动改主页和启动页，也不循环争抢其他扩展的新标签页设置。

浏览器隐私窗口不纳入 V1 的书签起始页支持范围；V1 不承诺接管隐私窗口，也不在其中主动展示普通模式的私人缓存。

### 9.3 发布前需要确认的决策

| 方案 | 收益 | 必须处理的代价 |
|---|---|---|
| 独立的可选起始页薄扩展 | 同步扩展不受影响，用户可单独启停 | 独立身份、授权、存储与发布流程 |
| 包含起始页覆盖的可选构建版本 | 更容易复用当前扩展运行时 | 版本切换、扩展 ID、更新渠道与缓存迁移 |

最终分发方案不在本文中假定已经拍板，但它是公开发布的阻断决策项。开发期间可以用显式安装的测试构建验证接管行为。

**若采用独立薄扩展，不能假定它能直接读取主扩展的 Device Token 或 IndexedDB。** 设计上使用独立最小读取授权，或另行审查明确的跨扩展通信；V1 优先避免新增跨扩展信任通道。

## 10. 视觉与组件规范

整体沿用 **Cold Rational Workspace**：白色与石墨灰为主体，低对比边框和冷灰建立层次，淡蓝只表达焦点、选择与交互。基础 Token 继续以 Mantine Theme 为准，Vanilla Extract 使用其 Token 完成产品布局，不新增独立全局色板。

起始页比 Explorer 更疏朗，但仍是工具页面，不采用营销式大标题或大面积背景图片。

| 元素 | 建议基线 |
|---|---|
| 主内容最大宽度 | 约 1120px，可在 1000–1200px 内调整 |
| 搜索框宽度 | 约 640px，窄屏按可用宽度收缩 |
| 搜索框高度 | 44px |
| 搜索区顶部留白 | 桌面约 64–96px，低高度窗口适度压缩 |
| 网格 | 桌面 4–6 列，窄屏减少列数 |
| 书签图标 | 24–28px，保持视觉克制 |
| 标题／次要文字 | 14px／12–13px |
| 入口圆角 | 6–8px |
| 阴影 | 仅用于 Menu、Popover 等浮层 |

普通卡片可以没有常驻边框，Hover 使用极轻背景，键盘 Focus 提供清楚的可见轮廓。文件夹与书签通过图标和辅助文字区分，不依赖颜色单独区分。

正常刷新只显示「内容已更新」或更新时间，不显示“所有设备已同步”，因为起始页快照无法代表其他设备状态。离线使用低干扰提示，授权失效和来源失效才提升视觉权重。

响应式至少覆盖 1366×768、1920×1080 和 375px 窄屏。长标题、长路径、200% 缩放、键盘操作和深浅主题均纳入验收。

## 11. 数据与权限边界

### 11.1 只读投影

新增 `StartPageProjection` 只负责读取与展示，不是 Replica，不具备写操作、Merge、Journal 回放或冲突解决职责。

禁止起始页读写同步核心的 `pending_operations`、`remote_changes`、`expected_mutations` 或修改 Binding watermark。缓存刷新也不能变相触发 Full Resync／Recovery。

V1 推荐由独立的只读快照接口供数，不直接把浏览器本地 Mirror 当作 Canonical 真相。已有同步事件可作为“缓存可能需要刷新”的提示，但不作为已完成展示更新的证明。

### 11.2 显式授权

Server 必须同时验证当前用户有效、Device／凭据有效、读取授权有效，以及来源仍属于该用户。资源 ID 本身不能充当授权。

起始页不引入独立的 Grant 对象（见 §0.1）。Server 用设备既有的绑定判断它能读什么：

1. `GET /api/v1/device/start-page/snapshot` 只接受 Device 凭据，并且只在该设备对此 Space 有 active 绑定时应答。门槛与 `/sync` 的快照读取一致，不是第二套判断。
2. 请求里的 `folder_id` 不构成授权：它只能在这个 Space 内解析，返回值限定为该文件夹的子树，不含其父级，也不含别的 Space。
3. 目录选择发生在扩展内，读取的是这台设备本来就能读的空间快照；不给任何凭据增加"遍历全部私人目录"的隐式权限，也不需要账户重新认证。
4. 绑定被解除或设备被撤销后，读取立即失败；这条不依赖前端隐藏。

### 11.3 当前来源内的读取

运行时默认只返回来源文件夹及其后代。页面面包屑从来源开始，不提供来源以上目录的可导航入口，也不让请求中的任意 `folder_id` 绕过范围校验。

Grant 允许展示来源名称、所属 Space 名称和来源内的相对路径。没有必要为起始页暴露其他 Space、原树无关的父目录结构或其他用户信息。

## 12. 建议的本地数据模型

以下是实现边界示意，不是要求新增一套完整持久化框架。

```ts
type StartPageSearchMode = 'web' | 'bookmarks';
type StartPageOpenTarget = 'current-tab' | 'new-tab';

type StartPageSearchProvider =
  | { kind: 'browser-default' }
  | { kind: 'preset'; id: string };

interface StartPageConfig {
  schemaVersion: 1;
  instanceId: string;
  userId: string;
  deviceId?: string;
  source: {
    spaceId: string;
    folderId: string;
    grantId?: string;
    grantVersion?: string;
  } | null;
  searchMode: StartPageSearchMode;
  searchProvider: StartPageSearchProvider | null;
  openTarget: StartPageOpenTarget;
  density: 'standard' | 'compact';
  configGeneration: number;
  updatedAt: string;
}
```

配置不保存凭据；凭据由既有认证模块管理。主题与语言沿用现有主题／偏好服务，避免在新结构中重复维护相互冲突的值。

缓存保存一份完整、验证通过的来源快照，至少包含 Server instance、账户、设备或访问环境、来源身份、Grant 版本、快照 epoch/revision、ETag、节点集合和最后验证时间。

`epoch/revision` 只用于快照标记与过期判断，不能作为起始页写入同步进度的依据。整数在线路上的编码应服从项目统一协议；若采用 64 位十进制字符串，Web 与 Extension 必须统一解码，不能一端按 number、一端按 string 隐式比较。

建议的本地集合为 `startPageConfigs` 与 `startPageSnapshots`。快照保留一个活动版本即可；取消来源或切换账户时，不保留用户不可见的旧缓存版本。

## 13. 只读 API 建议

本节定义新增能力的契约方向，路径可在接入现有 API 命名规范时调整。不得为了兼容这些建议名称另造第二套认证体系。

### 13.1 建议接口

| 接口 | 身份 | 用途 |
|---|---|---|
| `GET /api/v1/device/start-page/snapshot?space_id=…&folder_id=…` | Device 凭据＋该 Space 的 active 绑定 | 读取一个来源文件夹的完整子树快照 |

没有授权管理接口：来源是扩展的本地配置，Server 侧不保存起始页状态（§0.1）。范围校验由 Server 执行，不依赖前端隐藏。

### 13.2 响应示例

下例展示语义结构；示例中版本水位采用十进制字符串，实际接入时应与项目统一编码方式对齐。

```json
{
  "schema_version": 1,
  "instance_id": "instance-id",
  "user_id": "user-id",
  "source": {
    "space_id": "space-id",
    "space_name": "个人",
    "folder_id": "folder-id",
    "folder_title": "日常入口",
    "grant_version": "2"
  },
  "snapshot": {
    "epoch": "3",
    "revision": "18320",
    "captured_at": "2026-10-12T08:00:00Z",
    "complete": true
  },
  "nodes": [
    {
      "id": "bookmark-id",
      "type": "bookmark",
      "parent_id": "folder-id",
      "title": "GitHub",
      "url": "https://github.com/",
      "position": 0
    }
  ]
}
```

来源本身由 `source` 描述，`nodes` 包含其所有后代；直接子项的 `parent_id` 指向来源 ID。没有内容时返回 `nodes: []`，不返回 `null`。

快照中的元数据、水位和节点必须来自同一份一致性读取。不能先读取 revision，再用若干不受保护的查询拼出另一时刻的树。

### 13.3 缓存验证与错误

接口支持应用层保存的 ETag 与 `If-None-Match`。**必须先验证账户、设备、Grant 和来源是否有效，再决定是否返回 304。** 不得因为内容没有变化，就绕过撤销或禁用检查。

建议禁止共享缓存保存私人响应；ETag 和本地快照由应用明确管理。返回完整快照前执行节点数、解压后大小、树结构与身份范围校验。

| 错误码示例 | 行为 |
|---|---|
| `START_PAGE_NOT_CONFIGURED` | 引导选择来源 |
| `START_PAGE_SOURCE_UNAVAILABLE` | 来源不存在或不可用；不枚举未授权对象的信息 |
| `START_PAGE_SOURCE_TOO_LARGE` | 提示选择更小的文件夹；不截断成假完整快照 |
| `START_PAGE_SNAPSHOT_INVALID` | 不安装新快照，保留可用旧缓存并报告异常 |
| `START_PAGE_PERMISSION_REQUIRED` | 进入明确授权流程 |
| `DEVICE_CREDENTIAL_INVALID`／用户禁用 | 停止私人内容展示，清理对应展示缓存 |

涉及不存在与无权访问的响应，应遵循现有 API 的防枚举策略；不要为方便 UI 暴露其他用户的资源是否存在。

## 14. 缓存与刷新

### 14.1 扩展缓存优先

扩展内页面的加载顺序是：读取当前身份和配置，读取对应快照，立即呈现可用内容，然后通知后台尝试刷新。渲染已有缓存不应依赖后台网络请求成功。

缓存键必须至少隔离 `instance + user + device/environment + grant + source`。不能只用 `space_id`，更不能通过相同文件夹名称跨账户复用。

普通 Web 版首个页面加载先确认有效 Web Session，再展示该账户数据。Web 版允许使用数据缓存优化，但不承诺在 Server 完全离线时首次启动页面；不为本功能额外引入 PWA。

### 14.2 建议刷新节奏

以下数值是 V1 初始工程参数，不是平台上限，也不是已测性能结论。

| 场景 | 建议行为 |
|---|---|
| 首次配置／无缓存 | 立即获取完整快照 |
| 新开起始页且上次验证超过 60 秒 | 显示缓存并后台条件刷新 |
| 切回可见标签且超过 60 秒 | 发起合并后的刷新请求 |
| 页面持续可见 | 可每 5 分钟尝试刷新，不依赖精确计时保证正确性 |
| 用户手动刷新 | 立即验证，合并当前进行中的同源请求 |
| 既有同步发现相关 Space 变化 | 标记展示缓存待刷新，不写同步 watermark |
| 网络失败 | 退避重试，页面继续显示允许保留的缓存 |

同一扩展后台合并同一来源的刷新，避免打开十个标签页发起十份相同请求。正确性不能依赖内存去重始终存在；后台重启产生重复只读请求是可接受的，但旧响应覆盖新配置不可接受。

### 14.3 原子替换与异步竞争

下载、解析、验证全部完成后，才在本地事务中替换活动快照并更新时间。半包、解析失败、结构不完整或存储配额不足时，不能把当前好缓存替换成空数据。

每次请求绑定 `identityGeneration + configGeneration + grantVersion`。写入前重新检查这些值；用户在请求期间切换来源、退出或更换账户，旧请求的响应必须丢弃。

退出登录时还应取消进行中的请求并通知已打开页面停止展示。不能只删缓存，却允许稍后返回的旧请求把它重新写回。

### 14.4 离线与撤销

网络暂不可达时，扩展可展示最后一次获准缓存，并显示「离线 · 展示上次缓存」。首次没有缓存时只展示搜索与连接提示，不伪造空目录。

收到明确授权失效、用户禁用、来源失效响应后，立即清理该展示缓存并通知活动页面。只清理起始页数据，不误删同步 Pending 或用户离线编辑。

必须承认离线边界：**Server 无法远程收回已经落到离线设备上的明文缓存。** 本地退出立即清理；远程撤销要在设备重新联机并验证后生效。页面与帮助文案不能承诺离线设备上的即时远程擦除。

## 15. 页面状态与反馈

| 状态 | 内容表现 | 用户动作 |
|---|---|---|
| 未登录／未配对 | 搜索可用；不展示私人书签 | 登录或连接 Server |
| 未配置来源 | 简洁说明与来源选择入口 | 配置起始页 |
| 首次加载 | 维持页面结构的局部占位 | 等待或重试 |
| 来源为空 | 「这个文件夹还没有内容」 | 在工作台管理 |
| 正常 | 网格与弱化更新时间 | 浏览、搜索、打开 |
| 后台刷新 | 保留原内容，无全屏遮罩 | 可继续使用 |
| 离线且有缓存 | 缓存内容＋轻量离线提示 | 重试 |
| 离线且无缓存 | 不显示假内容 | 检查连接 |
| 来源失效 | 清空活动展示，不退回 Space | 重新选择 |
| 授权失效 | 停止私人内容展示 | 重新授权 |
| 来源过大 | 说明范围限制 | 选择更小目录 |
| 数据异常 | 拒绝新快照；有合法旧缓存时继续使用 | 重试／导出脱敏诊断 |

页面不得把“成功刷新快照”表述成“所有浏览器已同步”。文件夹导航和搜索本身不写 Activity，不生成用户后台 Job，也不在任务中心制造大量刷新记录。

## 16. 安全与隐私

### 16.1 URL 打开策略

标题、URL 和文件夹名称一律视为不可信内容，以文本渲染。`http:`、`https:` 通过统一安全 URL 工具打开；`javascript:`、`data:`、`file:`、浏览器内部协议和其他未支持协议在 V1 只提供复制，不在 Web 或扩展 origin 内执行。

用于安全判断的解析与协议检查不改变 Canonical 原始 URL。非法或包含混淆控制字符的 URL 不得在校验后原样绕过检查。`http/https` 的实际跳转应使用经过校验的解析结果。

用户主动点击 NAS 等内网书签属于用户浏览器导航；这不意味着 Server 可以替用户自动请求同一地址。起始页不执行链接扫描、预抓取、预连接或批量打开。

### 16.2 图标策略

V1 优先复用已有、可信来源的本地图标缓存，缺失时使用中性网站图标或字母占位。页面打开不能触发对每个网站的自动请求，也不默认调用第三方 favicon 服务。

若现有图标能力不满足该隐私边界，V1 使用占位即可，不为这一页面新建任意 URL 抓取服务。图标失败不能阻塞书签入口。

### 16.3 凭据与缓存

Device／API Token 不进入 URL、页面链接、诊断、快照或配置导出。页面需要的私人标题和 URL 可以存在授权缓存中，但本地缓存不是加密保险箱，不声称可以抵御读取用户浏览器 Profile 的攻击者。

日志默认仅记录错误码、数量、耗时和受控的内部标识，不记录搜索词、完整书签 URL 或请求体。普通诊断包不包含起始页缓存内容。

### 16.4 扩展权限

起始页沿用所需 Server 的 host permission，不为展示常用网站申请任意站点访问权限。仅在浏览器默认搜索功能需要时申请对应搜索权限，不因新页面增加 history、cookies 或网页注入能力。

保持扩展与 Web 的内容安全策略，不为方便第三方脚本、远程 UI 或自定义组件放开执行能力。跨 origin 读取通过明确凭据和目标访问权限完成，不能使用泛化 CORS 作为授权替代。

## 17. 技术架构与模块划分

沿用项目既定技术方向：Go＋SQLite＋手写 SQL；前端 TypeScript＋React 18＋Mantine＋Vanilla Extract；扩展 WXT；本地存储使用既有 IndexedDB／Dexie 基础设施。本文不重新冻结依赖版本，也不要求为了起始页迁移整个 Web Router。

```text
起始页 UI
    │
    ├── 当前层级展示与书签搜索
    ├── SearchAdapter
    └── StartPageDataProvider
             │
             ├── 扩展：账户隔离快照缓存＋后台刷新
             └── Web：Session＋只读快照读取
                              │
                              ▼
                     StartPageReadService
                              │
                     来源授权＋一致性读取
                              │
                              ▼
                       Canonical Tree
```

建议在 `web/src/features/start-page/` 和 `extension/src/core/start-page/` 分别放页面接入与扩展运行时，服务端增加边界明确的只读服务。只有出现真实重复时，再抽取 `packages/start-page/` 共享数据投影、搜索函数和无平台依赖的展示组件。

WXT 的页面入口与业务模块分离：`start-page` 用于普通扩展页面；`newtab` 仅在明确接管的构建中包含，并复用相同 App。普通 Web `/start` 的产物继续随 Web dist 嵌入 Go 二进制；扩展页面作为扩展自身资源打包，不从 Server 下载可执行界面代码。

本模块不得反向依赖同步 Merge Engine，不新增第三套书签身份映射，不直接操作浏览器 bookmarks API 来实现页面展示。

## 18. 数据量与性能目标

以下均是建议的 V1 验收预算，需要在目标设备与真实浏览器中测量，不代表已经达到。

| 项目 | 初始预算 |
|---|---|
| 单来源完整子树 | 最多 10,000 个后代节点 |
| 单快照解压后数据 | 最多 8 MiB；服务端与客户端共同限制 |
| 单次 DOM 呈现 | 当前层最多先显示 200 项，再按批加载更多 |
| 搜索可见结果 | 默认最多 100 项，并提示进一步缩小条件 |
| 已有缓存的扩展首屏 | 参考设备上 P95 不超过 500ms，不计浏览器自身启动 |
| 10,000 节点本地搜索 | 从输入稳定到结果更新，目标 P95 不超过 150ms |

超过范围时不得静默丢弃剩余节点，也不能把部分数据标记为 `complete: true`。V1 可明确拒绝过大来源，提示选择更小目录，而不是立即增加复杂分页快照协议。

当前层“加载更多”只是对完整快照的渐进渲染，不是向 Server 读取不同时间点的分页树。若测量发现同步搜索计算造成卡顿，再增加 Worker 或索引优化，不默认引入重型全文搜索系统。

记录性能结果时必须附浏览器版本、CPU、缓存大小与样本分布，不能只报告最快一次。

## 19. 开发阶段与验收门槛

### 阶段 A：只读契约与页面预览

实现来源选择、授权边界、完整快照与轻量网格，提供普通扩展预览页和 Web `/start`。不接管默认安装版本的新标签页。

验收：可以选择真实文件夹并下钻；更改来源不会创建 Sync Binding；快照接口只返回批准范围，空数组契约正确；起始页没有写书签能力。

### 阶段 B：搜索、缓存与多标签一致性

实现显式搜索模式、搜索提供商适配、本地快照缓存、条件刷新、配置代次防护，以及来源失效和授权失效处理。

验收：离线缓存可访问；退出后旧响应不能复活内容；多标签刷新不覆盖新来源；网页搜索只在显式提交后发生网络导航。

### 阶段 C：真实新标签页与浏览器接入

确认分发方案，提供显式安装的接管产物，验证安装、更新、禁用、卸载、冲突与恢复原生新标签页流程。Edge、Chrome、Firefox 分别报告验证结果，不把 Chromium 上的通过当成 Firefox 通过。

验收：用户清楚自己安装的版本是否接管；标准同步扩展不被意外加入覆盖声明；默认搜索能力与焦点行为符合实际浏览器表现。

### 阶段 D：内部发布与回归

补齐深浅主题、窄屏、键盘与大数据量测试，完成 Web embed 和扩展产物检查，更新用户文档与隐私说明。

验收：从首次安装、来源配置、日常使用、离线、权限撤销到卸载都有完整路径。UI 快照测试或 Fake API 测试不能替代真实浏览器验收。

## 22. V1 不变量

1. 起始页展示既有书签，不拥有第二棵树或独立排序。
2. 一个浏览器环境配置一个来源文件夹，使用 Canonical ID 绑定。
3. 展示范围受限于书签同步范围：起始页只显示这台设备已同步的空间，且只显示一个目录的子树。
4. 起始页不能创建同步绑定、写 Pending 或推进同步 watermark。
5. 缓存先验证再原子替换，旧身份／旧配置请求不得覆盖新状态。
6. 来源失效不扩大范围，授权失效不继续展示已确认失权的缓存。
7. 网页搜索与书签搜索必须显式区分，搜索词不被静默上传。
8. 页面配置开关不等于解除浏览器新标签页覆盖。
9. 标准同步扩展不能在普通升级中悄悄变成新标签页扩展。
10. 真实浏览器与真实 Server 的完整流程是发布依据，而不是单纯“页面能渲染”。
